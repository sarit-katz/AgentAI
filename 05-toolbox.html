ארגז הכלים: מה מוסיפים, ובאיזה סדר

40 additions · skills · MCP · plugins · memory

ארבעים תוספות ל-Claude Code, בחמש קטגוריות: בניית workflow, הוספת skills, שמירת קונטקסט, חיבור כלים, ופרומפטים ושימוש. הרשימה עצמה שימושית, אבל הכלל שמלווה אותה חשוב ממנה: אחד בכל פעם, על משימה אמיתית, לפני שמוסיפים את הבא.

הסיבה לכלל היא לא משמעת אלא מדידה. אם מתקינים שישה דברים בערב אחד, ואז העבודה מרגישה טובה יותר, אין דרך לדעת מי מהם עשה את זה - ומי מהם רק מוסיף קונטקסט לכל turn.

למה זה חשוב

התקנה ברירת המחדל של Claude Code היא בסיס, לא תקרה. הפער בין מי שעובד איתו שנה למי שהתחיל אתמול הוא בעיקר הפער הזה: skills שמכילים את הדרך שבה עובדים כאן, MCP servers שמחברים למקורות אמיתיים, וכלים שמצמצמים את מה שהמודל צריך לקרוא.

אבל לכל תוספת יש מחיר, וברוב המקרים הוא נמדד בקונטקסט. MCP server פתוח תופס מקום גם כשלא משתמשים בו. skill שנטען תמיד הוא בעצם CLAUDE.md מורחב. לכן הרשימה הזאת היא לא רשימת קניות - היא תפריט שממנו בוחרים לפי בעיה שקיימת, לא לפי מה שנשמע חדש.

הכלל: אחד בכל פעם

01

לבחור לפי בעיה

לא "מה חסר לי" אלא "מה עצבן אותי השבוע". אם אין תשובה לשאלה הזאת, אין מה להתקין.

02

לנסות על משימה אמיתית

לא על דוגמה. משימה שהייתה בכל מקרה, כדי שיהיה למה להשוות - זמן, איכות, וכמה קונטקסט זה עלה.

03

להחליט, ורק אז להוסיף

נשאר או יוצא. תוספת שנשארה "כי אולי" היא עלות קבועה בכל turn, בלי תועלת מוכחת.

הרשימה

כל 40 הפריטים, כפי שהגיעו, לפי קטגוריה. הסינון למעלה מצמצם לפי קטגוריה או לפי מילה בשם ובתיאור.

טוען את הרשימה…

מידע חסר · קישורים

הרשימה הגיעה כשמות ותיאורים בלבד, בלי כתובות. לא ייצרתי כתובות GitHub מהזיכרון, כי שם שגוי בכתובת שולח את מי שקורא למקום אחר לגמרי - ובמקרה של repo שמריצים ממנו קוד, זו טעות עם מחיר. פריט אחד כבר הושלם כך שצריך: הכתובת של graphify נמסרה, נבדקה מול GitHub ב-22.09.2026, ונכנסה לדאטה. מה צריך להשלים: שדה url לשאר הפריטים בקובץ assets/site-data.js. הרשימה כאן תתעדכן לבד, כי היא נגזרת מאותו קובץ.

ספריות מומלצות

הרשימה למעלה היא תפריט: ארבעים שמות, כמעט כולם בלי כתובת, כפי שהגיעו. הרשימה הזאת היא ההיפך - קצרה בכוונה, וכל שורה בה אומתה. לכל פריט יש כתובת repo, רישיון ופקודת התקנה שנלקחו מה-README עצמו ב-22.09.2026, ולא מהזיכרון. זה גם התנאי להיכנס לכאן.

הקריטריון השני הוא שהפריט פותר בעיה שכבר מופיעה באתר הזה: עיצוב שלא מתפרק, תכנון ששורד איפוס קונטקסט, וזיכרון ארגוני שלא נעלם בסוף השיחה.

טוען את הרשימה…

מה עוד צריך לבדוק לפני התקנה

רישיון וכתובת הם תנאי סף, לא אישור. skill ו-MCP server רצים בהרשאות שלך ועל הקבצים שלך - ולכן גם כאן הכלל הוא אחד בכל פעם, על משימה אמיתית, עם פסק דין כתוב. המספרים בתיאור של ui-ux-pro-max הם דיווח ה-repo, לא מדידה שלנו.

השיחות נגמרות באמצע, או שהעלות מרגישה גבוהה שמירת קונטקסט הקטגוריה היחידה שמשפיעה ישירות על שני הדברים - ראי נושא 02

אין דרך קבועה לעבור ממשימה לתכנית ולביקורת בניית workflow מסגרת שלמה שמחליפה זרימת עבודה מאולתרת. הקטגוריה הכי פולשנית - להיכנס בזהירות
אין לך מושג לאן הולך השימוש פרומפטים ושימוש ניטור וצמצום פלט. זול להתקין, ומייד נותן תמונה

מה עושים בפועל

קובץ אחד בתיקיית הפרויקט, שמתעד מה נכנס, למה, ומה החלטת. בלי זה הארגז הופך לשכבה שאף אחד לא יודע להסביר - וזה בדיוק מה שמקבל מי שיבוא אחרייך.

להשאיר MCP servers פתוחים כל server צורך קונטקסט בכל turn, גם בשיחה שלא נוגעת בו /mcp - לסגור מה שלא בשימוש עכשיו
להריץ קוד מ-repo שלא נבדק skill או plugin הוא קוד שרץ אצלך, עם ההרשאות שלך לקרוא מה שהוא עושה לפני התקנה. ריפו בלי תחזוקה - לא נכנס
להפוך workflow לחוק לפני שהוא הוכח כל הצוות עובד לפי מסגרת שאף אחד לא בדק על עבודה אמיתית אדם אחד, שבועיים, ואז להחליט אם זה נכנס ל-CLAUDE.md

מדריך החלטה

  1. איזו בעיה מהשבוע האחרון זה פותר? אם אין בעיה קונקרטית, התשובה היא לא להתקין. עניין הוא לא בעיה.
  2. מה זה עולה בקונטקסט? נטען תמיד או לפי הצורך? /context בשיחה טרייה נותן את התשובה במספרים.
  3. קראת מה הקוד עושה? skill ו-MCP server רצים בהרשאות שלך, על הקבצים שלך. זה לא תוסף דפדפן.
  4. מי יתחזק את זה כשלא תהיי כאן? בחפיפה זו השאלה המכריעה. מה שאף אחד לא יודע להסביר - צריך לצאת לפני המסירה.

שאלות שחוזרות

skill הוא הוראות - טקסט שנטען כשהוא רלוונטי. MCP server הוא חיבור לכלי או למקור חיצוני. plugin הוא אריזה שיכולה להכיל את שניהם ועוד. המשמעות המעשית: skill עולה קונטקסט, MCP server עולה קונטקסט וגם פותח דלת למערכת אמיתית.
המיפוי. חמש הקטגוריות מראות אילו סוגי בעיות בכלל נפתרים בתוספת, וזה מה שמכריע לפני הבחירה. את השם עצמו אפשר לחפש; קישור שגוי - לא. לכן שדה הקישור נשאר ריק ומסומן ככזה, ומתמלא כשכתובת נמסרת ונבדקת - כמו שקרה עם graphify.
זה בדיוק מה שצריך להיות מסומן לפני החפיפה. הרשימה כרגע היא תפריט חיצוני, לא מצב קיים. מיפוי מה מותקן, אצל מי, ומה הפסק דין - נמצא ברשימת ההשלמות בעמוד היכולות.
